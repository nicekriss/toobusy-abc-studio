## 실제 오디오와 브라우저

- 정답이 있는 5초 합성 파일: MIDI [61,60,66,65,69,69,70,69], 각 시작 .3초부터 .5초 간격, 길이 .36초. 파일 선택→서버 분석→미리듣기 생성→새 악보 반영까지 확인. 추출 8개 음 모두 정답, 시작 시각 일치, 추출 길이 .37초(정답 대비 +10ms).
- 사용자 로컬 생성 노래 15초 구간: 브라우저 디코딩·스테레오 구간 추출·WAV 업로드·HDemucs 보컬 분리·pYIN·템포 추정까지 완료. 56개 음, 추정 126.05 BPM. **정답 악보가 없어 실제 곡의 음정·리듬 정확도 비율은 측정하지 않았다.** 이 결과는 전체 음악 장르의 품질 보증이 아니다.
- 원본·분리 보컬·합성 멜로디 오디오가 정상 로드. 합성 멜로디를 일반 클릭으로 끝까지 재생하고 media error 없음 확인.
- 새 악보 반영 후 되돌리기: 이전 ABC 텍스트가 완전히 동일하게 복원되고 조·BPM·성부·코드 복원 확인.
- 잘못된 분석 방식은 HTTP 400, 중복 작업은 409, 취소 후 해당 작업은 404. Windows 리디렉터와 자식 작업 프로세스 2개를 실제 관찰하고 취소 후 모두 종료된 것을 확인.
- 최종 서버 코드에서 동일한 원본 15초를 44.1kHz로 변환해 재검사: 전체 처리 24.21초, 57개 음, 추정 126.05 BPM. 브라우저 리샘플러와의 차이로 음표 수가 1개 달라졌다.
- Codex 내장 브라우저의 네이티브 오디오 접근성 버튼 자동 조작에서 검증 탭이 한 번 종료됨. 새 탭에서 실제 좌표 클릭으로 재생은 정상 완료. 다른 브라우저 전체에 대한 호환성 인증은 하지 않음.

## 범위

진단용 오디오·모델·사용자 원본은 저장소에 포함하지 않는다. 모델은 공식 PyTorch 다운로드와 고정 SHA-256으로 검증한다. 보컬 분리 흔적, 합창, 잔향, 꾸밈음에서 틀린 음이 남을 수 있으므로 결과를 미리듣고 편집하는 작업을 전제로 한다.

## 마이크 성부 선택 검증

- `tests/js/microphone.test.mjs`: 인스/보컬 목적지, 현재 탭·재생 위치 변경, 성부 재정렬, 새 성부 생성·재사용, 무음의 무변경, 악보 교체·템포 변경 거부, 배음이 있는 440Hz 신호의 선택 성부별 ABC 출력을 검사했다.
- 실제 8188 설치본의 별도 브라우저에서 종류 선택 시 `Ins Melody` / `Vocal Melody` 대상 표시 전환을 확인했다.
- `tests/browser/microphone.html`은 실제 마이크를 열지 않고 Web Audio 440Hz 신호를 MediaStream으로 제공하는 수동 검증 화면이다. 검증 시에만 확장의 `js/microphone-test.html`에 복사하고 `/extensions/toobusy-abc-studio/microphone-test.html`에서 연다. 검증 후 설치본에서 제거한다.
- 임의의 기존 성부 `Custom`에 도레미파 4개가 있는 악보에서 녹음 시작→준비 박자→녹음 중지→분석→ABC 반영을 실행했다. 인스를 고르면 `V:Ins`, 보컬을 고르면 `V:Vocal`에 라(A4) 1개가 들어갔고 기존 4개 음은 보존되었다. 각 녹음을 되돌린 ABC 텍스트는 녹음 전과 완전히 동일했다.
- 녹음 중 인스/보컬 선택 입력이 비활성화되고 중지 후 다시 활성화되는 것을 확인했다.
- 연결을 8초 지연시킨 뒤 창을 닫았을 때, 뒤늦게 반환된 스트림이 즉시 중지되고 악보와 닫힌 창이 유지되었다. 권한 거부를 모의했을 때 오류 안내 후 시작 버튼이 복구되고 악보는 바뀌지 않았다. 브라우저 오류 로그 없음.
- 이번 검증은 성부 선택과 녹음 동작의 검증이다. 실제 사람이 허밍하거나 가사로 노래한 음원의 채보 정확도는 측정하지 않았다.
